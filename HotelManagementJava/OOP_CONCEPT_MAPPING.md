# OOP Concept Mapping Guide

Use this table during your practical evaluation or viva to quickly point your teacher to the exact file and method where each syllabus topic is implemented.

| Concept | File / Class | Method or Code Location | What the Code Does | How I Can Explain It to My Teacher |
| :--- | :--- | :--- | :--- | :--- |
| **1. Primitive Data Types (`int`, `double`, `char`, `boolean`) & `String`** | `Room.java` | Instance variables (`roomNumber`, `pricePerNight`, `floorCode`, `isAvailable`, `roomType`) | Stores room number (`int`), nightly tariff (`double`), floor letter `'A'`/`'B'`/`'C'` (`char`), availability (`boolean`), and room category (`String`). | "In `Room.java`, I used four different primitive types (`int`, `double`, `char`, `boolean`) along with the `String` class to represent the state of each room." |
| **2. Arithmetic, Relational, Logical & Increment Operators** | `Room.java`, `Booking.java`, `HotelManagementSystem.java` | `Room.determineFloorCode()`, `Booking.calculateBill()`, `HotelManagementSystem.addGuest()` | Uses `>=`, `<`, and `&&` to check room number ranges (`100 <= n < 200`); `*`, `+`, `-`, `/` for bill calculation; and `++` (`nextGuestId++`, `availableCount++`) to increment counters. | "In `determineFloorCode()`, I combined relational (`>=`, `<`) and logical (`&&`) operators, and in `HotelManagementSystem` I used the post-increment operator (`++`) to auto-generate unique Guest and Booking IDs." |
| **3. Type Conversion & Explicit Type Casting** | `Booking.java` | `calculateBill()` and `calculateLoyaltyPoints()` | `pricePerNight * numberOfNights` performs implicit widening (`int` to `double`). `(int) exactPoints` performs explicit narrowing cast from `double` to `int`. | "In `calculateLoyaltyPoints()`, `exactPoints` is a `double`. Since loyalty points must be whole numbers, I used explicit type casting `(int) exactPoints` to truncate the decimal portion." |
| **4. Conditional Statements (`if-else` and `switch`)** | `Main.java`, `Room.java` | `Main.main()` (`switch(choice)`), `Room.determineFloorCode()` (`if-else if-else`) | `switch` routes menu options `1` to `10` to their respective methods; `if-else` validates room availability, nights stayed, and floor codes. | "I used a `switch` statement in `Main.java` for clean multi-way branching across the 10 menu choices, and `if-else` statements for range checks and input validation." |
| **5. Loops (`do-while`, `for`, `while`)** | `Main.java`, `HotelManagementSystem.java` | `Main.main()` (`do-while`), `displayAllRooms()` (`for`), `loadBookingsFromFile()` (`while`) | `do-while` runs the menu at least once until exit (`choice != 10`); `for` iterates through arrays/lists; `while` reads lines from the text file until end-of-file (`null`). | "I used all three loops where each fits naturally: `do-while` for the menu because the menu must show at least once, `for` for indexed array traversal, and `while` when reading an unknown number of lines from a file." |
| **6. Classes and Objects** | `Room.java`, `Guest.java`, `Booking.java`, `HotelManagementSystem.java` | `initializeRooms()` (`new Room(...)`), `addGuest()` (`new Guest(...)`), `bookRoom()` (`new Booking(...)`) | Defines blueprints (`Room`, `Guest`, `Booking`) and instantiates objects in memory using the `new` keyword. | "A class is a blueprint, and an object is a real instance created with `new`. For example, `Room` is the class, while `rooms[0] = new Room(101, \"Single\", 1500.0)` is an object representing Room 101." |
| **7. Constructors & Constructor Overloading** | `Room.java`, `Guest.java`, `Booking.java` | `Room(int, String, double)` vs `Room(int, String, double, boolean)`; `Guest` (4-arg vs 3-arg constructor) | Provides multiple constructors in the same class with different parameter lists to initialize objects in different ways. | "In `Room.java`, I overloaded the constructor: the 3-parameter constructor sets `isAvailable = true` by default, while the 4-parameter constructor lets us specify availability explicitly. Java picks the right constructor at compile time based on the arguments passed." |
| **8. Encapsulation** | `Room.java`, `Guest.java`, `Booking.java` | `private` fields + `public` getters/setters (e.g., `setPricePerNight()`, `setAvailable()`) | Hides internal fields using `private` so external classes cannot corrupt data directly, and exposes controlled access via `public` getters and setters. | "Encapsulation binds data and methods together and hides internal state. In `Room.java`, all fields are `private`, and `setPricePerNight()` checks `if (pricePerNight > 0)` before updating the price." |
| **9. Access Modifiers (`private`, `protected`, `public`)** | `Person.java`, `Room.java`, `Main.java` | `protected String name` in `Person`; `private int roomNumber` in `Room`; `public` service methods | Demonstrates `private` (class-only), `protected` (accessible in subclasses like `Guest`), and `public` (accessible everywhere). | "In `Person.java`, `name`, `age`, and `contactNumber` are `protected` so the child class `Guest` can access them directly, whereas `guestId` in `Guest` is `private` to `Guest`." |
| **10. Inheritance (`extends` and `super`)** | `Person.java` -> `Guest.java` | `public class Guest extends Person` and `super(name, age, contactNumber)` | `Guest` inherits `name`, `age`, `contactNumber`, and getters/setters from `Person`, reusing code and adding `guestId`. | "`Guest` extends `Person` because a Guest IS-A Person. Inside the `Guest` constructor, `super(name, age, contactNumber)` calls the parent `Person` constructor to initialize inherited fields." |
| **11. Method Overloading (Compile-Time Polymorphism)** | `Booking.java` | `calculateBill()`, `calculateBill(double discountPercent)`, `calculateBill(double discountPercent, double extraFoodCharges)` | Three methods with the exact same name `calculateBill` but 0, 1, and 2 parameters respectively. | "In `Booking.java`, `calculateBill` is overloaded three times: with no parameters for a standard stay, 1 parameter to apply a discount percentage, and 2 parameters to include both a discount and extra food charges." |
| **12. Method Overriding & Runtime Polymorphism** | `Person.java`, `Guest.java`, `HotelManagementSystem.java` | `Guest.displayDetails()` (`@Override`), called in `HotelManagementSystem.addGuest()` via `Person personReference = newGuest; personReference.displayDetails();` | Child class `Guest` overrides `displayDetails()` and `getRole()`. A parent reference (`Person`) points to a child object (`Guest`) and invokes the overridden method at runtime. | "In `addGuest()`, I wrote `Person personReference = newGuest; personReference.displayDetails();`. Even though the reference type is `Person`, Java's Dynamic Method Dispatch calls `Guest.displayDetails()` at runtime because the actual object is a `Guest`." |
| **13. Abstract Class & Abstract Method** | `Person.java` | `public abstract class Person` and `public abstract String getRole();` | Prevents instantiating a generic `Person` object directly and forces every subclass (`Guest`) to implement `getRole()`. | "`Person` is declared `abstract` because a hotel never registers a generic 'Person'—only specific roles like `Guest`. The abstract method `getRole()` has no body in `Person` and is implemented by `Guest`." |
| **14. Interface** | `Billable.java`, `Booking.java` | `public interface Billable` and `public class Booking implements Billable` | Defines `GST_RATE = 0.12` (`public static final`) and the `calculateBill()` method contract implemented by `Booking`. | "`Billable` is an interface defining the billing contract and GST constant. `Booking implements Billable` guarantees that `Booking` provides the `calculateBill()` implementation." |
| **15. Arrays vs `ArrayList` (Object Collections)** | `HotelManagementSystem.java` | `private Room[] rooms = new Room[8];` and `private ArrayList<Booking> bookings;` | Uses a fixed-size array `Room[]` for the 8 physical hotel rooms and dynamic `ArrayList`s for guests and bookings. | "A hotel has a fixed number of physical rooms, so a fixed-size `Room[]` array is ideal. However, the number of bookings grows and shrinks as guests book or cancel, so I used `ArrayList<Booking>` for dynamic resizing." |
| **16. Passing Objects & Returning Objects from Methods** | `Booking.java`, `HotelManagementSystem.java`, `SyllabusConceptsDemo.java` | `new Booking(bookingId, guest, selectedRoom, nights)`, `findRoomByNumber()`, `SyllabusConceptsDemo.demonstratePassByValue()` | Passes `Guest` and `Room` object references into methods/constructors and returns `Room`, `Guest`, and `Booking` objects from search/creation methods. | "Java is strictly Pass-by-Value. When we pass a `Room` object to `Booking`, Java passes a copy of the reference by value, allowing both variables to refer to the same `Room` object in heap memory." |
| **17. Recursion** | `HotelManagementSystem.java` | `calculateTotalRevenueRecursive(int index)` | Recursively sums `totalCost` across all bookings in `bookings`. Base case: `index >= bookings.size()` returns `0.0`. Recursive case: adds current booking cost to `calculateTotalRevenueRecursive(index + 1)`. | "In `calculateTotalRevenueRecursive(int index)`, the base case stops recursion when `index` reaches the end of the booking list (`return 0.0`), and the recursive step adds the current booking's bill to the result of `index + 1`." |
| **18. The `final` Keyword** | `Booking.java`, `HotelManagementSystem.java` | `Booking.FIXED_SERVICE_FEE = 100.0`, `HotelManagementSystem.HOTEL_NAME` | Declares constants whose values cannot be reassigned after initialization. | "I used `public static final` for constants like `HOTEL_NAME` and `FIXED_SERVICE_FEE = 100.0` so their values remain fixed throughout program execution." |
| **19. Exception Handling (`try`, `catch`, `finally`)** | `Main.java`, `HotelManagementSystem.java` | `Main.readIntInput()`, `HotelManagementSystem.saveBookingsToFile()`, `loadBookingsFromFile()` | Catches `NumberFormatException` when a user types letters instead of numbers, and catches `IOException` during file operations while closing streams in `finally`. | "In `readIntInput()`, a `try-catch` block catches `NumberFormatException` so typing `'abc'` at the menu prints a friendly warning instead of crashing. In `saveBookingsToFile()`, the `finally` block ensures the `BufferedWriter` is always closed." |
| **20. File Handling (Text Persistence)** | `HotelManagementSystem.java` | `saveBookingsToFile()` and `loadBookingsFromFile()` | Writes bookings as CSV lines to `data/bookings.txt` using `FileWriter`/`BufferedWriter` and reads them back using `FileReader`/`BufferedReader`. | "`saveBookingsToFile()` converts each `Booking` object into a comma-separated string using `toFileString()` and writes it with `BufferedWriter`. `loadBookingsFromFile()` reads each line with `BufferedReader`, splits by comma, and reconstructs the objects." |
| **21. Static Nested Class vs Non-Static Inner Class** | `SyllabusConceptsDemo.java` | `static class HotelTaxRules` vs `class BranchBadge` in `demonstrateNestedAndInnerClasses()` | Separate demonstration class showing how a `static` nested class is instantiated without an outer object, whereas a non-static inner class requires an outer instance and accesses outer fields. | "To keep the main booking code simple, I demonstrated nested classes in `SyllabusConceptsDemo.java`: `HotelTaxRules` is a `static` nested class, while `BranchBadge` is a non-static inner class that accesses `hotelBranchName` of the outer object." |
| **22. Multithreading & Synchronization (`Runnable`, `start`, `join`, `synchronized`, `wait`, `notify`)** | `SyllabusConceptsDemo.java` | `SharedRoomCleaningMonitor`, `ReceptionTask`, `HousekeepingTask`, `demonstrateMultithreading()` | Separate demonstration class where `Reception-Thread` calls `wait()` until `Housekeeping-Thread` cleans the room and calls `notify()`, using `synchronized` methods and `join()`. | "In `SyllabusConceptsDemo.java`, two threads (`ReceptionTask` and `HousekeepingTask`) implement `Runnable` and share a `SharedRoomCleaningMonitor` object. The reception thread waits (`wait()`) until housekeeping finishes cleaning and wakes it up (`notify()`)." |
